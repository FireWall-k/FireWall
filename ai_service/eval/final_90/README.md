# 최종 평가셋 — 신규 90문항 (2026-09-25)

개발·튜닝에 쓰지 않은 문장 90개(9개 직무 × 10)로, 사업주가 업종을 넣어 직무를 만드는 **실제 서비스 경로**를 잰다.
결과 보고서 표 11의 근거 자료다. **이 문항으로 스코어러를 튜닝하지 말 것** — 튜닝에 쓰는 순간 신규 문항이 아니게 된다.

| 파일 | 내용 |
|------|------|
| `final_set.py` | 90문항 (직무별 10개) |
| `ops_eval.py` | 서비스 경로 실행 스크립트 → `ops_runN.json` |
| `ops_run1.json`, `ops_run2.json` | 운영 설정(LLM·임베딩) 두 회차 원자료 |
| `ops_grading.md` | 문항별 판정·집계 규칙 |

## 결과 (운영 설정: gpt-4o-mini + text-embedding-3-large/256, 이미지 1058장)

| 회차 | 자동 선택률 | 자동 선택 정밀도 | 오답률 | 정답률 |
|------|------|------|------|------|
| 1 | 51.1% (46건) | 60.9% [46.5~73.6] | 10.0% [5.4~17.9] | 31.1% [22.5~41.3] |
| 2 | 51.1% (46건) | 58.7% [44.3~71.7] | 10.0% [5.4~17.9] | 30.0% [21.5~40.1] |

[ ]는 95% Wilson 신뢰구간. 판정 기준·집계 규칙·한계(판정자가 대체 경로 행과 다름)는 `ops_grading.md`.

## 재현

```bash
# 저장소 루트: 서비스를 띄운다(운영 설정이면 .env에 OPENAI_API_KEY)
docker compose up -d
cd ai_service/eval/final_90
pip install httpx
python ops_eval.py 3
```

LLM 분해는 실행마다 조금씩 다르다(두 회차 사이 18문항 출력이 달랐고, 집계 변동은 ±1건).
